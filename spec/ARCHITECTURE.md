# ARCHITECTURE: סל חכם

מבוסס על `PRD.md`, `tech-stack.md`, `course-stack.md` ו-`product-10-definitions.md`. נכתב ב-20.10.2026, ועודכן ב-24.10.2026 לפי הערות המשתמש.
המסמך מתאר מה בונים ואיפה כל חלק יושב. אין בו Milestones ואין בו לוח זמנים.


### צד לקוח
- אתר סטטי ב-GitHub Pages: HTML, CSS ו-JavaScript, בלי כלי בנייה ובלי ספריות.
- דף אחד, `index.html`, עם שלושה מסכים כ-`section`. JavaScript מציג מסך אחד בכל פעם:
  1. **בניית הסל:** רשימה של 67 המוצרים מתוך `data/products.json`, עם חיפוש לפי שם. לכל מוצר כפתור הוספה וכמות. כפתור "השווה" לא פעיל כשהסל ריק.
  2. **המלצת חלופות:** מוצג רק כשמוצר בסל חסר ברשת אחת לפחות. לכל חלופה: הרשת, המוצר החסר, המוצר המוצע, "אשר" ו"דחה".
  3. **פלט תוצאות:** עלות לכל רשת, סימון "הזול ביותר", "חלקי, חסרים N מוצרים" ו"חלופה", רשימה נפרדת של מוצרים שלא נמצאו באף רשת, שהיא ההתראה למשתמש, והם לא נכנסים לסל, והכיתוב "מחירי מדף, לא כולל מבצעים".
- הסל והחלטות החלופות נשמרים ב-localStorage.
- הדפדפן קורא מחירים ישירות מ-Supabase, עם המפתח הציבורי, דרך ה-REST API של Supabase (`fetch`).
- כל החישוב בדפדפן, בקוד: מחיר כפול כמות, סכום לכל רשת, והכלל של סל חלקי.
- עברית מימין לשמאל, קודם לטלפון ברוחב 375 פיקסל, ועובד גם במחשב.

### לוגיקה
- **פונקציה אחת ב-Vercel:** `api/substitutes.js`. היא הרכיב היחיד שמחזיק את מפתח Gemini ואת המפתח הסודי של Supabase. פירוט בסעיף 4.
- **n8n על המחשב של יוני** (Community Edition): Workflow אחד שמושך את קבצי המחירים משלוש הרשתות וכותב ל-Supabase. פירוט בסעיף 5.
- **חישוב עלות הסל:** בדפדפן, לא בפונקציה ולא במודל.

### נתונים
- **Supabase:** שתי טבלאות, `chain_items` ו-`substitutes`. פירוט בסעיף 2.
- **קבצי JSON בריפו:** רשימת 67 המוצרים (`data/products.json`) והרשתות והסניפים (`data/chains.json`). הם קבועים, ולכן לא בטבלה.
- **localStorage:** הסל של המשתמש והחלטות החלופות שלו.

## 4. שכבת ה-AI

**מתי:** אחרי "השווה", כשמוצר בסל חסר ברשת אחת לפחות, ואין לו עדיין חלופה במטמון.

**המסלול:**
1. הדפדפן שולח ל-`/api/substitutes` רשימה של זוגות: רשת וברקוד חסר. עד 67 זוגות.
2. הפונקציה בודקת קודם בטבלה `substitutes`. מה שכבר קיים, ושהחלופה עדיין קיימת ב-`chain_items`, חוזר בלי מודל.
3. לכל זוג שנשאר, הפונקציה מחפשת בקוד מועמדים ב-`chain_items` של אותה רשת, לפי `keywords` של המוצר. עד 30 מועמדים לכל מוצר.
4. קריאה אחת ל-Gemini לכל הזוגות שנשארו, עד 10 בקריאה.
5. הקוד בודק את התשובה, שומר ב-`substitutes`, ומחזיר לדפדפן.

**מה נשלח למודל:** לכל מוצר חסר: השם והגודל מ-`products.json`, ורשימת המועמדים (קוד, שם, יצרן, כמות, יחידה). בלי מחירים, כי הבחירה לא תלויה במחיר.

**מה חוזר (מבנה קבוע, JSON):**
```json
[{ "chain_id": "tiv_taam", "missing_barcode": "7290000000001",
   "suggested_item_code": "7290000000099", "reason": "אותו סוג חלב, 1 ליטר" }]
```

**שלוש המגבלות בפרומפט:**
1. בחר רק `item_code` מתוך רשימת המועמדים שקיבלת. אסור להמציא מוצר או מחיר.
2. רק מוצר מאותו סוג ובגודל קרוב. אם אין כזה, החזר null. אל תחליף בשקט בין סוגים, גדלים או כמויות.
3. התבסס רק על הרשימה שקיבלת, לא על ידע כללי. אם אין מוצר מתאים, דווח null במקום לנחש.

**בדיקת התשובה בקוד:** מבנה ה-JSON תקין, כל `suggested_item_code` קיים ברשימת המועמדים שנשלחה, ואחרת הוא הופך ל-null והמוצר מסומן "חסר ברשת".

**המודל:** Gemini Flash בשכבה החינמית. שם המודל במשתנה סביבה `GEMINI_MODEL`. אם Gemini מחזיר שגיאת מכסה (429), הפונקציה מנסה פעם אחת עם `GEMINI_FALLBACK_MODEL`, Gemini Flash-Lite.

**בדיקות:** `ai-tests.md` בריפו, עשרה מקרים לפחות: מוצר חסר, רשימת מועמדים, החלופה הצפויה או null. היעד מה-PRD: לפחות 8 מתוך 10 סבירות, ואפס מוצרים מומצאים.

## 5. אינטגרציות, APIs ואוטומציות

### n8n: Workflow אחד, `daily-prices`
- **הפעלה:** Schedule Trigger פעם ביום (פיצ'ר 7ב), ו-Manual Trigger לטעינה ידנית (פיצ'ר 7א). שניהם מפעילים את אותו המשך.
- **שלושה ענפים, אחד לכל רשת:**

| מס' | רשת | הפורטל | מה הענף עושה |
|---:|---:|---:|---:|
| 1 | שופרסל | prices.shufersal.co.il | מוצא את קובץ ה-PriceFull העדכני של הסניף, ומוריד |
| 2 | טיב טעם | Cerberus, url.publishedprices.co.il | נכנס עם שם המשתמש של הרשת מה-Credentials, מוצא את קובץ ה-PriceFull של הסניף, ומוריד |
| 3 | ויקטורי | laibcatalog.co.il/victory | מוצא את קובץ ה-PriceFull העדכני של הסניף, ומוריד |

- **בכל ענף, אחרי ההורדה:** פריסת gz (Compression), קריאת XML, Code node שממפה לשדות של `chain_items` ומסנן מוצרים במשקל, ו-upsert ל-Supabase דרך ה-REST API, במנות של עד 1,000 שורות.
- **כשל:** אם ענף נכשל, הוא לא מוחק שורות. הטבלה נשארת עם המחירים האחרונים, והאתר ממשיך לעבוד איתם. n8n שומר את הכשל ביומן ההרצות שלו.
- **מגבלה:** המחשב צריך להיות דלוק בשעת המשיכה.
- **תוצאת לוואי:** כתיבה יומית ל-Supabase שומרת את הפרויקט פעיל, ולכן הוא לא מושהה אחרי שבוע בלי פעילות.

### Gemini API
נקרא רק מ-`api/substitutes.js`, דרך REST, עם המפתח ממשתנה הסביבה.

### Supabase REST API
- הדפדפן: קריאה מ-`chain_items` ומ-`substitutes`, עם המפתח הציבורי.
- n8n והפונקציה: כתיבה, עם המפתח הסודי.

### `api/substitutes.js`: החוזה
- `POST`, גוף: `{ "missing": [{ "chain_id": "...", "barcode": "..." }] }`. עד 67 פריטים. בקשה גדולה יותר נדחית.
- תשובה תמיד JSON: `{ "results": [...] }`, או `{ "error": "..." }` עם הודעה כללית, בלי הודעה גולמית של ספק.
- CORS: רק מהכתובת של האתר ב-GitHub Pages. עונה גם ל-OPTIONS.

## הנחות והחלטות
- **שתי טבלאות ולא אחת לכל רשת:** `chain_id` מבדיל בין הרשתות, וזה פשוט יותר מטבלה לכל רשת.
- **`chain_items` שומרת את כל הסניף, ולא רק 67 מוצרים:** בלי זה אין מועמדים לחלופה. אלפי שורות לכל רשת נכנסות בנוחות בשכבה החינמית של Supabase. זו הערכה, ולא נמדדה.
- **מטמון `substitutes`:** לפי דיווחי מפתחים, המכסה החינמית של Gemini Flash היא כ-20 בקשות ביום. מטמון וקריאה אחת לכמה מוצרים שומרים עליה.
- **סינון מועמדים בקוד, לפי `keywords`:** חישוב, השוואה וסינון נעשים בקוד ולא במודל, וזה גם מגביל את אורך הקלט למודל.
- **טבלת הסטנדרטיזציה היא `products.json`:** ההגדרה אומרת שה-AI בונה אותה מראש, בפיקוח. ההחלטה: בונים אותה פעם אחת בבדיקת הנתונים, בעזרת AI בצ'אט ולא דרך קוד, ושומרים בריפו.
- **`fetch` במקום ספריית Supabase:** בלי כלי בנייה ובלי תלויות. ה-REST API של Supabase מספיק לקריאה ולכתיבה פשוטות.
- **דף אחד עם שלושה מסכים:** הסל והחלטות החלופות עוברים בין המסכים בלי לטעון דף מחדש.
- **ה-AI בצד השרת (תשובה לשאלה 3 בהגדרה, 24.10.2026):** ה-AI רץ רק בפונקציה ב-Vercel. המשתמש רק מזין את הסל, ומסך התוצאות מציג עלות כוללת לכל רשת, בלי מחיר לכל מוצר. חישוב הסכום עצמו נשאר בדפדפן, ולכן המחירים כן מגיעים לדפדפן מ-Supabase, עם המפתח הציבורי.
- **החלטות חלופה ב-localStorage:** החלטה של משתמש שייכת לסל שלו, ואין שרת שמזהה אותו.
- **שמות הקבצים בפורטלים, הפרמטרים לחיפוש ושם המשתמש של Cerberus לא נבדקו מבפנים,** כי האתרים לא נגישים מהשרת שבו נכתב המסמך. בודקים אותם בבדיקת הנתונים.
- **כלל הנתונים בשכבה החינמית:** נשלחים למודל רק שמות מוצרים ציבוריים, בלי מחירים ובלי מידע אישי. נשאר לאשר מול המרצה, כמו שכתוב ב-`tech-stack.md`.
